# v0.8.0 · Phase 7: review console

The claims handlers' console, with no credential in the browser.

## Included

- **Review console** (`web/console`, Angular 22 with standalone components and signals, in
  Spanish). Inbox by queue; for each claim the facts, the rules' evaluation (decision, payable
  amount, routing, reasons, rule corrections, fraud score and signals), why the agents asked for
  review, the cited clauses with their text, the documents as read with doubtful fields and
  embedded instructions flagged, and the audit trail.
- **Review form**: approve, correct (decision and amount) or reject, mirroring the core's checks
  for clear messages; the core validates again and its problem details are shown. Each
  submission carries an idempotency key.
- **No credential in the browser** (ADR 0015): an unprivileged nginx serves the build and proxies
  `/api` to the core, adding the REVIEWER key from the environment. Strict Content-Security-Policy
  with no inline script. `make console-up` runs it as a compose profile.
- **Tests**: 12 Vitest unit tests, and 3 Playwright tests in CI against the console container and
  the core: a payment approved through the console ends paid, with the review and payment in the
  audit trail and no console errors; no request or downloaded file carries the key; a rejection
  without a comment is refused before sending.
- **Found by the end-to-end test**: `crypto.randomUUID()` only exists in secure contexts, so the
  console could not open a claim when served over plain HTTP on an internal host. Idempotency
  keys now come from `crypto.getRandomValues`.
- The agents keep their review requests in the proposal's metadata, so the handler sees why.

## Known limitations

- Reviewers are not individually authenticated: whoever reaches the console reviews as the
  console. Production needs OIDC and per-user sessions (ADR 0009, ADR 0015).

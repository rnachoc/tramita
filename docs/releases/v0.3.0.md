# v0.3.0 · Phase 2: core system and rules

The insurer's system of record, and the rules that decide what the agents may and may not do.

## Included

- **Core service** (Java 17, Spring Boot 3.5, PostgreSQL, Flyway): policies, claims, documents and
  their masked extractions, agent proposals, human reviews, payments and an audit trail.
- **Rules engine**, pure Java, checking every proposal in a fixed order: policy in force, guarantee
  included, waiting period, grounded exclusion, required documents, amounts, notice period, fraud,
  citations and routing. The code computes every payment; disagreements with the proposal are
  recorded as violations and always go to a person. Only consistent payments up to 3,000 EUR and
  requests for catalog-required documents run automatically.
- **Fraud scoring**: signals from the rules plus signals from the model with quoted evidence,
  combined with catalog weights; 0.4 sends a claim to review, 0.7 to investigation. Nothing is
  rejected for fraud without a human.
- **Safety properties**: API keys with roles (the agent service can propose but never review or
  pay), idempotent writes, one payment per claim enforced by the database, an append-only audit
  trail enforced by a trigger, evidence frozen once a claim leaves assessment, and errors that name
  the field to fix.
- **Verification**: 41 Java tests, including integration tests against PostgreSQL and a cross-check
  in which the Java engine agrees with the dataset's independent Python resolver on all 150 claims.
  CI also sends each compose service a real request, runs the core against the stack and seeds it,
  and builds every pushed commit on its own.

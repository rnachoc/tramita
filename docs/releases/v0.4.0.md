# v0.4.0 · Phase 3: document reading

Claim documents read without any personal data reaching the model, and checked by code.

## Included

- **Model client** with one interface for the Anthropic API (structured outputs, vision, prompt
  caching; model ids in configuration), a recorder, and a fake model that replays recordings or
  answers with a labelled rule-based responder, so everything runs without a key (ADR 0010).
- **Personal data masking** with Presidio and the Spanish spaCy model: NIF, NIE, IBAN, phones,
  e-mail, names, plates and street addresses, with fallbacks for what OCR damages. Values become
  stable tokens per claim (`<PERSON_1>`); company tax ids, amounts, dates and document numbers stay.
- **Scans**: Tesseract OCR at about 300 dpi, words laid out in visual rows, personal data blacked
  out in the image. The model gets the redacted image and the masked OCR text; PDFs are sent as
  masked text only.
- **Extraction checked in code**: strict schema, parsing, CIF control digit, line/tax/total
  arithmetic, and a lookup of every value in a second reading give each field its confidence.
  Key fields below 0.6 go to review, and doubtful facts are never sent to the rules.
- **Prompt injection**: documents quoted as data, the model reports embedded instructions, and a
  deterministic detector flags them independently.
- **Ingestion** (`make ingest`): store the original in S3, read, register with the type read,
  record the extraction in the core. Idempotent.
- **Evaluation** (`make eval-extraction`) with a CI gate. Rule-based baseline on 233 documents:
  100% classification and key fields on PDFs and scans, 0 wrong facts sent to the rules (1,071
  sent), 0 of 1,044 personal values reaching the model, the redacted scans or the core, 0 rule
  values lost to masking, planted instructions found in 3 of 3 PDFs with no false alarms.
- **Verification**: 141 Python tests. CI also ingests a sample of claims end to end against the
  stack and the core and checks them through the API and the object store.
- **ADRs 0010 and 0011**.

## Known limitations

- Very small print is invisible to OCR: instructions planted that way in scans (3 of 3) are left
  to the vision model, and personal data printed that small would not be blacked out.
- Evaluated only with the rule-based baseline: no API key is configured in CI, so there are no
  real-model numbers yet.

# v0.11.0 · Phase 10: observability and cost

One trace per claim across the agents and the core, metrics and a dashboard, and cost per claim,
with no content in any of it.

## Included

- **Agent traces with the OpenTelemetry GenAI conventions**: `process_claim` > `analyse_claim` >
  `invoke_agent` per agent > `chat` per model call (provider, model, tokens) and `execute_tool`
  per tool call > `policy_search` with its stage timings; `read_document` per document. Spans
  carry identifiers, counts, models, outcomes and timings, never text (ADR 0018).
- **Core traces and metrics**: Micrometer tracing with the OpenTelemetry bridge, joined to the
  agents' spans by `traceparent`; Prometheus metrics with request latency by URI template and
  `tramita.proposals` by decision and routing.
- **Observability stack** as a compose profile (`make obs-up`): OpenTelemetry collector (which
  also deletes message-content attributes), Jaeger, Prometheus and Grafana with a provisioned
  overview dashboard.
- **Cost report** (`make cost-report`): model calls, tokens and wall time per agent and claim, and
  dollars for models whose price is configured in `TRAMITA_MODEL_PRICES`; no price is guessed.
- **Verification**: every processed claim is one trace with both services and every expected span
  kind; none of the ground truth's personal values (1,800 checked) appears in the traces; CI runs
  the agents on every claim with telemetry on and checks Jaeger and Prometheus.
- **Found by measuring**: the SDK's default histogram buckets suit milliseconds, so Grafana showed
  keyless model calls at a p95 of about 4.75 s. Buckets now follow the GenAI conventions, with a
  test, and CI fails if keyless calls read as slow.
- **Tests**: 235 Python, 54 Java.

## Known limitations

- Keyless runs use no tokens, so cost is zero until a key and prices are configured.
- Debugging a wrong answer uses the proposal and its masked rationale, not the trace, by design.
- Counters read right after a batch lag the last scrape: CI counted 149 claims analysed and 148
  proposals evaluated of 150, because the core stops as soon as the batch ends. Traces are exact
  (150 of 150).

# v0.9.0 · Phase 8: MCP server

Read-only tools for analysts' assistants, with every result masked for the model.

## Included

- **`tramita-mcp`** (official MCP Python SDK 2.x, stdio or streamable HTTP): tools to search the
  policy conditions (the hybrid search), list claims, read one claim with its latest evaluation,
  citations, fraud signals and review requests, read its audit trail and count claims by status;
  resources with the rules in order and each product's conditions.
- **Guarded by the core's roles** (ADR 0016): the server reads with the ANALYST key, which the
  core allows nothing else; every tool is declared read-only.
- **Masked for the model**: descriptions masked like documents; no incident address, contact
  details, reviewer names or account numbers; the text the reader flagged as embedded
  instructions is never returned, only counted.
- **Verified end to end in CI over stdio**: all 150 claims read with none of the 1,650 personal
  values of the ground truth in any result; a search returns citable clauses; the server's key
  gets 403 when it tries to write.
- **Core fix**: behind a real servlet container a known key without the role got 401 instead of
  403 (the error was forwarded to `/error` without the key). A test over HTTP covers it and fails
  without the fix.
- **Intermittent crash on exit, explained and fixed**: the fault handler added in v0.7.0 caught
  it in CI as `PyGILState_Release` while a short-lived command that had used the Temporal client
  was exiting; its native threads raced interpreter shutdown. Such commands now end without
  finalisation once their output is flushed.
- **OpenSearch in the smoke test**: the check waits for the node to accept connections, after a
  CI run where a node that had just reported healthy reset the first one.
- **Tests**: 221 Python, 53 Java.

## Known limitations

- Every MCP user acts as the server's ANALYST client; per-user identity needs OIDC.
- Analysts see no personal data through the assistant, even where their role would allow it.

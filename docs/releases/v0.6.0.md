# v0.6.0 · Phase 5: agents

Claims analysed by agents that judge, a coordinator in code, and rules that decide.

## Included

- **Agent loop** on the plain SDK (ADR 0003): typed read-only tools, the answer as a `submit`
  tool validated against the output schema, tool errors returned to the model, a step budget and
  a timeout. Every model client takes tool-use steps; recordings store each step and the fake
  replays them or asks a deterministic step responder (ADR 0010).
- **Coordinator in code** (ADR 0013): guarantee included, waiting period and required documents
  checked without a model. The **coverage agent** searches the product's conditions (phase 4)
  for an exclusion; the **damage agent** marks which repair lines belong to the incident and code
  adds them up; the **fraud agent** reports signals whose quoted evidence must appear in the claim.
  Grounding citations come from the clause index the core checks.
- **Agents can only escalate**: review requests from any agent, or from documents with embedded
  instructions, make the core route the claim to a person (`REVIEW_REQUESTED`, new in the core,
  with tests). Nothing an agent returns can lower a routing.
- **`make process`** submits a proposal for every open claim; **`make eval-agents`** compares the
  core's decisions with the expected resolutions. CI ingests and analyses all 150 claims and
  gates the outcome.
- **Results without an API key** (deterministic baselines that read nothing): decision correct
  96.2%, exclusions 10 of 14 with none proposed wrongly, 1 rule violation, **0 claims settled
  automatically that a person should have seen** (10 before the baselines asked for review).
- **Verification**: 197 Python tests, 43 Java. Run end to end against the local stack and in CI
  with the same numbers.

## Known limitations

- No real-model numbers: CI has no API key. Without a model every payment goes to a person
  (routing as expected 58.0%), which is the honest reading of "nobody read this claim".
- The baselines miss unrelated repair lines and document/incident mismatches; those claims reach
  a person, but six mismatch frauds go to review rather than investigation.

# v0.12.0 · Phase 11: Kubernetes

Tramita as a Helm chart with hardened pods and deny-by-default networking, tested inside a kind
cluster.

## Included

- **Container images** for the core and the agent service: multi-stage, non-root (uid 10001),
  running with a read-only root file system; the agents image carries Tesseract with Spanish data
  and downloads the search models into a volume.
- **Helm chart** `deploy/helm/tramita` (ADR 0019): the core, the agents' API, worker and bridge,
  the review console, a job that indexes the policy conditions, and optional single-replica
  infrastructure with the Compose images (PostgreSQL with pgvector, Kafka, OpenSearch, RustFS,
  Temporal).
- **Hardened pods**: non-root, read-only root, all capabilities dropped, `RuntimeDefault`
  seccomp, no service account token.
- **Secrets** generated at install time and kept on upgrade; none in values or the repository.
- **Network policies**: ingress denied by default and allowed per component.
- **`helm test`**: one pod analyses a sample of claims end to end inside the cluster; another,
  with no allowed role, must reach the console and nothing else.
- **Verified** on kind locally (Kubernetes 1.37): all pods ready, index built, 12 claims analysed
  in the cluster, network policies enforced. **CI** lints the chart, validates the manifests with
  kubeconform against the 1.34 schemas, and installs and tests it on kind.

## Known limitations

- Development-grade infrastructure: single replica, no backups, OpenSearch's security plugin off
  (only the agent pods can reach it). Production would use managed services.
- No ingress controller, TLS or OIDC; the console is reached with a port-forward.
- The search models sit on a ReadWriteOnce volume, shared by pods on one node.

# v1.0.0 · Phase 12: wrap-up

All twelve phases complete: an AI agent system that processes insurance claims end to end, where
the model proposes and the code decides.

## Included in this release

- **`make demo`**: the whole pipeline on a fresh clone without credentials (stack, synthetic data,
  policy search index, core, ingestion, agents and their report). The core keeps running so the
  claims can be reviewed in the console.
- **`make eval`**: every evaluation (document reading, policy search, agents) and the comparison
  with the committed baseline.
- **Documentation checked against fresh evaluation runs**; two stale document reading figures
  corrected in the README.

## What Tramita is, at 1.0

- **Core system** (Java 17, Spring Boot): rules engine, deterministic fraud scorer, idempotent
  payments, append-only audit trail, API keys with roles.
- **Document reading** with personal data masked before any model, trace or log, and planted
  instructions treated as data.
- **Hybrid policy search** (BM25 + pgvector + reranker), measured with its own evaluation.
- **Coverage, damage and fraud agents** coordinated in code; agents can only make a claim safer.
- **Events and workflows**: transactional outbox to Kafka, one Temporal workflow per claim.
- **Review console** (Angular) and a read-only **MCP server** for analysts.
- **Evaluation baseline and scorecard** gating every headline number in CI.
- **Observability** with the OpenTelemetry GenAI conventions, and a cost report.
- **Helm chart** with hardened pods and network policies, tested on kind in CI.

## Known limitations

- No real-model numbers: CI and the baseline run keyless, with deterministic baselines that read
  nothing and escalate every payment.
- Reviewers and MCP users are not individually authenticated (no OIDC).
- The chart's infrastructure is development-grade: single replica, no backups, no ingress or TLS.
- `make demo` was verified through the same steps in CI, not end to end on the maintainer's
  machine.

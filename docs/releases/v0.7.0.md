# v0.7.0 · Phase 6: events and long-running processes

Claim events on Kafka from a transactional outbox, and one durable Temporal workflow per claim.

## Included

- **Outbox over the audit trail** (ADR 0014): every committed change in the core is already in
  its append-only audit trail; a relay publishes it, in order, to `tramita.claim-events`, keyed by
  claim, and moves its cursor only after the broker acknowledges. Gaps from transactions still in
  flight are waited for; old ones are rollbacks and are skipped. At least once, deduplicated by
  `event_id`. Only listed fields leave the core: no names, no account numbers, no descriptions.
- **Event contract** in Pydantic, `docs/events/claim-event.schema.json` generated
  (`make event-schemas`) and checked for drift in Python and against the relay in Java.
- **Consumers** with manual commits, in-place retries with capped exponential backoff and a
  dead-letter topic per consumer group; messages that break the contract are parked at once.
- **ClaimWorkflow** on Temporal: analyse the claim, wait for missing documents (then analyse
  again) or for a claims handler's review (then read the final status), each with a deadline;
  end when paid or rejected. Signals carry the event id, so replayed events are ignored and a
  signal that arrives during an analysis is not lost.
- **Bridge** from claim events to workflow signals; `make worker`, `make bridge`,
  `make start-claims`.
- **Verification**: 214 Python tests (the workflow on Temporal's time-skipping test server), 51
  Java (the relay against real PostgreSQL and Kafka). CI runs the loop on the stack: twenty
  workflows, a review approved through the API reaches its workflow through Kafka and the claim
  ends paid; events stay in order per claim with no personal data, and the dead-letter topic is
  empty.

## Known limitations

- One relay per core instance; running several would need a lock on the relay row.
- Overdue workflows end and wait for a person to chase them; no reminders yet.
- One CI run hit an intermittent segmentation fault as a short-lived command exited; it did not
  recur, and the step now runs with a fault handler to show where if it does.
- No real-model numbers for the agents yet (unchanged from v0.6.0).
